# End-to-end simulations, 2026-10-09

Three requests driven through the whole factory loop by headless `claude -p`
sessions loading this checkout as the plugin: a small bug fix, a medium
feature as two stacked slices, and a large feature as four slices in three
waves. Each fixture's `lawbook.yaml` extends lawbook's clean-code example and
`factory.toml` sets `llm = true`, so the model-judged standards ran on every
green tree.

Tool versions: lawbook 0.3.0, poly-crap 0.8.2, Claude Code with the default
model, pnpm 11.25, uv 0.11.7.

## Factory defects found and fixed on this branch

1. **verify.sh skipped the model-judged stage for any config that uses
   `extends`.** The guard grepped the top-level `lawbook.yaml` for
   `standard:`; the clean-code rules live in the extended file. The stage
   now asks `lawbook check --dry-run`, which sees the whole config.
   `faa97da`.
2. **The request cap was an undocumented `MAX_REQUESTS=20` from the
   environment.** It is now `[verify].max_requests`, default 50, in
   `factory.toml` and the setup reference. The medium run's second slice
   needed 26 requests. `faa97da`.
3. **verify.sh hid every change under `src/` when a source file sat at
   the repository root.** The stack globs were split unquoted, so `*.ts`
   expanded to `vitest.config.ts` and the pathspec collapsed to that file;
   stages 1 to 3 then reported "no changed source files" on the node
   fixture. `*.py` with a `conftest.py` does the same. Fixed with `set -f`
   and a regression test. `8d1a4df`.
4. **The Stop hook depended on the model writing `.factory/loop.local.md`
   by hand.** The small run wrote it with a blank session id; the medium
   run skipped it, so the hook never armed. `verify.sh --loop` now writes
   the file itself and the implement skill runs `/factory:verify --loop`.
   `8d1a4df`, `666a259`.
5. **No skill owned `docs/specs/<slug>/`.** It stayed untracked through
   implement and simplify, and the pr skill met an uncommitted plan and
   broke its own refuse rule, saying so. The slice commit now carries the
   spec directory, the plan skill says so, and the implementer agent does
   the same. Confirmed in the medium run: both slice commits include the
   docs and every tree was clean. `2a54eba`.
6. **A fresh repository has no `factory` label**, so the first `gh issue
   create` failed and the plan skill recovered by creating it. The tracker
   notes now create the label first. `2a54eba`.
7. **Stage 7 printed FAIL lines and then "verify: clean".** Failed
   model-judged standards do not gate by design; the summary now says so.
   `d293b28`.
8. **The plan allowed a slice blocked by two independent chains.** A
   base-branch stack has one parent per slice, so the implementer copied
   slice 01's commit into slice 04 and the pr skill then refused the PR.
   The plan rules now require every blocker to be an ancestor of the
   slice's `Parent`, serializing chains instead. `c4910c5`.
9. **Implementers were told to push, and a global rule against unasked
   pushes won.** Pushing now belongs to `/factory:pr` only, which already
   did it in every run. `c4910c5`.
10. **Agent worktrees kept the slice branches checked out**, under the
    repository's own `.claude/worktrees/`, so the main checkout could not
    switch to them and the parent's untracked plan copy blocked checkout
    too. The implement skill now removes each agent's worktree once its
    branch is green, and setup ignores `.claude/worktrees/`. `c4910c5`.

## lawbook

Filed:
[drew-simmons/lawbook#56](https://github.com/drew-simmons/lawbook/issues/56),
standard rules spend a model request on an empty file. Reproduced with a
two-file config: the empty `__init__.py` costs one request per standard rule,
twelve on the clean-code example.

Observed and not filed:

- The clean-code standards are judged per changed file, so a slice that
  touches a file inherits findings on code it did not write
  (`formatStatus` in the medium run). `--since` works at file level; a
  baseline hides known findings but has to be maintained. This is a
  design limit worth a docs note rather than a bug.
- Judgments were consistent with the independent reviewer agent's
  findings in both runs, and the `deep-modules` warning on a one-function
  module was a fair reading of the rule.
- `extends` resolved both ways: a relative path on the python fixture and
  the `lawbook/examples/clean-code.lawbook.yaml` package specifier on the
  typescript fixture.

## Harness notes

Failures caused by the driver, not by factory, all fixed in
`simulations/`:

- A fixture checkout under this worktree's `.claude/` path made Claude
  Code deny every write as a sensitive config edit, and reads of the
  vendored upstream files the same way. Checkouts now live under
  `SIM_WORK_ROOT` and the plugin loads through a symlink outside `.claude/`.
- The plan check wanted bare tracker URLs; rumdl's autofix wrapped them in
  angle brackets.
- The verify probes ran on an already stamped tree and read the wrong log.
- The simplify-commit stage fired on untracked docs with nothing to
  commit.
- The status fixture's `status` script could not run under type stripping
  with `.js` import specifiers; the fixture now imports `.ts` paths.
- A check expected the green stamp to survive committing previously
  untracked files; it does not, because untracked files are hashed as raw
  content and tracked ones as diff text.
- After `implement --all` the driver switched branches without releasing
  the agent worktrees or the parent's untracked `docs/` copy, so the
  large run's tail had to be rerun by hand from simplify with
  `SIM_APPEND=1`; the records of the aborted attempt were dropped.

## Open questions, resolved after the runs

- **`allowed-tools` did not grant `coderabbit auth status`.** A minimal
  plugin skill with `Bash(coderabbit:*)` runs `coderabbit --version` with
  no denial in headless mode, and the same skill is denied when it runs
  `/Users/<user>/.local/bin/coderabbit --version`. The review session had
  used the absolute path. The review skill now says to invoke the CLI by
  bare name. Not a Claude Code bug.
- **Should fail-level standards gate?** Yes. Stage 7 now records lawbook's
  exit 1, so a `fail`-level standard fails verify like any other stage;
  `warn`-level rules, the three taste rules in clean-code, stay advisory.
- **Stacked slices judged since `origin/main`.** verify.sh now reads the
  current branch's `Parent` from `plan.md` and uses it as the base when
  the ref exists, so floor, lint, lawbook, and poly-crap see the slice
  alone. `BASE=<ref>` still overrides.

Still open:

- With `--all`, the parent updates `plan.md` in the main checkout while
  each slice commit carries its own copy, so the two drift. The tracker
  item is the source of truth for status; plan.md in a branch is a
  snapshot. Worth saying in the plan skill.
- The Stop hook's run inside implementer agents was not captured: their
  worktrees were removed before the evidence was copied. The small run
  shows the hook working in a single session.
