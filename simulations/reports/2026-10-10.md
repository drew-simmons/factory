# Simulations, 2026-10-10

Four runs of the loop after the close-the-gaps stack (v0.5.0) merged:
`small-bug`, `medium-feature`, `large-feature`, and the new `orchestrated`
run that drives the large feature through `/factory:run` alone. Every run
was repeated after a fix, so this report is four batches, not one.

## Setup, and what this batch could not measure

The runs were driven from a Claude Code cloud session whose GitHub access is
scoped to this repository and blocks GraphQL. `gh issue create`, `gh pr
create`, and `gh pr view --json` all need GraphQL, so no stage that touches
the forge could run. The harness gained `SIM_FORGE=0` for this: a local bare
repository stands in for GitHub so `origin/main` resolves and pushes land,
the fixture tracker becomes local files, and every stage or check that
needs the forge is recorded as skipped. The `pr`, `pr --stack`, and
steward paths, and the GitHub tracker, are therefore unmeasured here and
still need a run from a machine with a real token.

Headless `claude -p` with the default model. Budgets as in the run
scripts. `uuidgen` and `column` were missing in the container and
installed; `pass` is not needed when `GH_TOKEN` is set.

## Batch 1: the denial check pays for itself

Every stage of every run tripped the new free check "no tool call was
denied", and nothing else of substance failed. The denials were all one
thing: compound Bash commands. Heredocs to write `spec.md` and `plan.md`,
`verify.sh ... | tail` and `; echo exit=$?`, chains with `&&` and `$(...)`.
A prefix tool grant denies the whole command, and the skills' own
`allowed-tools` are prefix grants too, so this bites real users, not only
the harness.

The consequences were real. In `small-bug`, `simplify` never ran verify
inside its session because its one verify call carried `; echo exit=$?`.
In `large-feature` and `orchestrated`, both implementer agents issued a
compound command first, read the denial as "Bash is denied", and stopped
the slice: `implement --all` built nothing.

Everything else worked. Spec, plan with `plan-check` exit 0 and local issue
files, implement with the Stop hook disarming on green, the review handoff
file with one `[P3]` finding, and the orchestrated run's two gates: `run.md`
written, `Waiting on` set, and a fresh session resuming from it.

Two findings from the first `small-bug` run stand on their own:

- The model-judged lawbook stage flagged a pre-existing test in a file the
  slice touched, and the Stop hook made the implementer fix it. The review
  then flagged that edit as scope creep (P3). Per-file judging means a
  slice inherits findings on code it did not write. The previous report
  observed this and did not file it; it is not lawbook #56, which was
  empty files costing a model request each and is fixed in lawbook 0.3.1
  (#57), the version these runs used. A line-level scope in lawbook would
  close it.
- The planner for `large-feature` put the rounding fix (slice 01) on its
  own root branch to avoid the diamond `plan-check` now rejects, then wrote
  slice 04's acceptance to depend on 01's behaviour. `plan-check` sees
  branches, not behaviour. The plan skill now says so.

Fix: a shell discipline rule in every skill and both agents (one command
per Bash call, no `&&`, `;`, pipes, redirects, or `$(...)`; a denied
command is not a denied tool; files through Write and Edit), verify run as
the whole command, agents running tests through the package manager, and a
few plain tools added to the harness allowlist.

## Batch 2: zero denials, and `implement --all` builds three slices

`small-bug` and `medium-feature` passed every check they could run, with
zero denials across twenty sessions. `large-feature`'s `implement --all`
built slices 01, 02, and 03 with verify exit 0 each, in ten minutes for
$1.24, and refused to commit slice 04 red: its test needed slice 01's
rounding fix, which was not on its parent chain. The refusal is the rule
working; the plan shape is the finding above.

Twenty of its 27 failed checks were one harness bug: the driver cleans the
untracked spec copy after `implement --all`, which removed the `plan.md`
every later check read. Fixed by reading the copy the driver saves first.
The agents still had one or two denials each, all Bash writes under
`.claude/worktrees/` (copying the spec directory with `cp`, `tee -a`, a
Python one-liner writing a file), which headless Claude Code treats as
config edits. Write and Edit were fine, and the agents recovered. The
implementer agent now says to bring the spec directory in with Read and
Write.

`orchestrated` reached `implement --all`, built slice 01, and then its
parent ended the turn while slice 02's agent ran in the background, to
"wait for the completion notice". A headless session ends with the turn,
so the agent was orphaned.

## Batch 3: the background agent trap

With the rule "wait for every agent in the foreground" in the implement
skill, both the orchestrated parent and the large-feature parent still
ended their turns with an agent in the background. The orchestrated parent
said it had asked for foreground and the agent ran in the background anyway,
tried a shell sleep loop to wait, and was denied. Prose alone does not fix
this; the Agent tool needs `run_in_background: false` spelled out, and the
loop needs to be resumable, which it is by design: `run.md` recorded exactly
where to continue, and `implement --all` recomputes the frontier from the
branches.

A second harness bug surfaced here: the saved plan copy from the previous
run was never cleared and sorted ahead of the live plan, so every branch
check compared against last run's names.

Fix: `run_in_background: false` named in the implement skill, the drivers
resume the loop from disk the way a user would (once for `implement --all`,
up to twice for `/factory:run`) and record how many resumes it took, and
the saved plan is cleared per run.

## Batch 4: the loop closes, with resumes

`large-feature`: the planner cut five slices this time. `implement --all`
built 01 to 03 and again ended its turn with slice 04 in the background;
the one resume built 04 and 05. Every slice has its commit, 04 and 05
stacked on their parents, verify exit 0 each, and the end-to-end checks
on the statement and balance commands pass. Review on slice 05 found four
P3 findings, all scope creep and a test gap, which `--from-review` left
unchecked as designed. The eight failed checks: the commit citation regex
rejected `(slice 01, R13)` although the skill shows only `(01, R13)`; the
post-fix clean-tree check failed because an all-P3 review leaves its file
untracked; slice 04's evidence directory was not copied before its
worktree was released; and two denials, a `find` outside the repository
and a bare `.venv/bin/python -m pytest` in simplify. The first two were
harness strictness and are loosened.

`orchestrated`: `/factory:run large` reached the PR gate with two
resumes, in six sessions for $4.46. Each resume read `run.md`, found the
orphaned worktree with uncommitted edits, saved the partial diff, removed
the worktree, relaunched the slice, and went on. All three slices were
built, simplified, and reviewed; the review of slice 03 found two P2s (a
`--month 0000-09` traceback, a function the model-judged standards wanted
split) and `--from-review` fixed both; slice 03 was restacked onto the
fixed 02 before its review. `run.md` carries one log line per step with
the commit or evidence path. The two failed checks: two resumes were
needed instead of one, and `Waiting on` was written as a sentence instead
of the template's `pr`. The run skill now says the field takes exactly
the template's values.

The parent's `run_in_background: false` was not honoured in headless mode
in any of these runs, so the resume path is the one that works there.
Whether an interactive session honours it is untested here.

## Factory defects found and fixed in this batch

1. Compound Bash commands denied whole; agents stopping on one denial.
   Shell discipline rule in every skill and agent; verify run bare.
2. Implementer agents orphaned when the parent's turn ends. Explicit
   `run_in_background: false`; the loop resumes from disk.
3. Bash writes under `.claude/worktrees/` denied as config edits. Agents
   use Write and Edit for the spec copy.
4. A slice depending on another slice's behaviour across disjoint files.
   Plan rule; `plan-check` cannot see it.

Harness: offline mode, forge checks skipped not failed, the saved plan
copy read after the live one and cleared per run, a slice kept red
tolerated, resume stages, and the offline tracker check.
